# Документация проекта NovusWarden (От А до Я)

**NovusWarden** — высокопроизводительный self-hosted менеджер паролей и корпоративных секретов с архитектурой **Zero-Knowledge**, разработанный и поддерживаемый командой **SGC-NOVUS (System Generations Core Novus)** на базе апстримного **Vaultwarden** и протокольной совместимости с **Bitwarden**.

## 2. Руководство пользователя (Web Vault, Расширения, Мобильные клиенты)

### 2.1 Быстрый старт и регистрация
1. Откройте Web Vault и нажмите **Создать аккаунт** (`#/signup`).
2. Укажите email, опциональное имя и надёжный мастер-пароль.
3. Проверьте **Язык интерфейса и писем (Email)** — определяется автоматически из настроек браузера (`ru`, `uk`, `en`) и может быть уточнён перед регистрацией или изменён позже в **Настройках → Мой профиль**.
4. Все новые аккаунты регистрируются с принудительным усиленным криптопрофилем **Argon2id** (`64 MiB`, `3` итерации, `4` потока, соль `SHA-256(lowercase(email))`).

### 2.2 Поддерживаемые клиенты Bitwarden
NovusWarden совместим со всеми официальными клиентами Bitwarden:
- **Браузерные расширения:** Chrome, Chrome Beta, Firefox, Edge, Safari, Opera, Brave, Vivaldi
- **Десктоп и Mobile:** Windows, macOS, Linux, iOS, Android (включая Push Relay и SignalR MessagePack-синхронизацию)
- **Bitwarden CLI (`bw`)**: полная поддержка `bw config server <URL>`, `bw login`, `bw sync`

### 2.3 Основные функции хранилища
- **Типы записей:** Логины (с URI Match Detection и TOTP), Банковские карты, Личные данные, Защищённые заметки, SSH-ключи, а также расширенные типы v2026+ (`BankAccount`, `DriversLicense`, `Passport`).
- **Дополнительная защита:** вложенные папки (`Проект/Продакшн`), `Master Password Reprompt`, история паролей, пользовательские поля, вложения файлов, корзина и архив.
- **Novus Send:** зашифрованная передача текста и файлов с паролем, сроком действия и ограничением числа просмотров (ключ не уходит на сервер — передаётся после `#` в URL).
- **Novus Sentinel:** клиентский аудит слабых, коротких, повторяющихся паролей и паролей без 2FA.
- **Двухфакторная аутентификация и вход:** TOTP, Email OTP, WebAuthn / Passkeys, Recovery Code, **Login with Device** (Auth Requests) и **Экстренный доступ**.

## 3. Руководство по организациям (B2B и команды)

В разделе **Организации** (`#/organizations`) доступны все возможности корпоративного управления:
1. **Создание организации:** ключ организации (`OrgKey`) создаётся локально в браузере и шифруется вашим публичным RSA-ключом.
2. **Участники:** приглашение по email, криптографическое подтверждение публичного RSA-ключа, смена ролей (`Owner`, `Admin`, `Manager`, `User`), отзыв (`Revoke`) / восстановление (`Restore`) доступа.
3. **Коллекции и группы:** гранулярное разделение доступа к записям (включая `ReadOnly` и `HidePasswords`).
4. **Политики безопасности:** обязательная 2FA, сложность мастер-пароля, Single Org, отключение Send, сброс пароля администратором организации и др.
5. **Аудит и MFA:** журнал событий (`Event Logs`), экспорт хранилища организации и настройка Org Duo 2FA.

## 4. Руководство администратора (Развёртывание и Control Plane)

### 4.1 Запуск через Docker Compose
Используйте готовый минималистичный [docker-compose.yml](../docker-compose.yml) (лимит памяти `512M`, резерв `64M`):
- Образ: `ghcr.io/sgc-novus/novuswarden:latest`
- Web Vault на Vue 3 включён по умолчанию (`WEB_VAULT_VUE=true`).
- Полный перечень переменных окружения задокументирован в [.env.template](../.env.template).

### 4.2 Безопасность панели администратора (`/admin`)
- Используйте Argon2id PHC-строку вместо открытого пароля:
  ```bash
  novuswarden hash
  ```
- Обязательно задайте `ADMIN_EMAIL` и почтовый транспорт (`SMTP_*` или `RESEND_API_KEY`): при 2 неудачных попытках входа в админ-панель срабатывает блокировка **Novus Sentinel**, и ссылка экстренной разблокировки (`/admin/unlock?token=...`) отправляется на `ADMIN_EMAIL`.

### 4.3 Базы данных и объектное хранилище
- **SQLite (по умолчанию):** режим WAL, требует менее 30 МБ RAM; поддерживаются горячие снимки (`VACUUM INTO`) из админ-панели.
- **PostgreSQL / MySQL:** задаются через `DATABASE_URL`; миграция с SQLite на PostgreSQL выполняется скриптом `tools/migrate_sqlite_to_postgres.py`.
- **S3 / Cloudflare R2 / MinIO:** единый бэкенд Apache OpenDAL для хранения вложений, Sends и конфигов.

## 5. Криптографическая безопасность и прозрачность (Zero-Knowledge)

1. **Изоляция секретов на клиенте:** Мастер-пароль никогда не передаётся и не хранится на сервере. Сервер получает только `masterPasswordHash` (PBKDF2 от derived key, не позволяющий восстановить `MasterKey`) и уже зашифрованные ключи/записи.
2. **Шифрование данных:** Каждая запись и вложение шифруются по схеме **AES-256-CBC + HMAC-SHA256** (`EncType 2`). Совместные ключи организаций используют **RSA-2048 OAEP**.
3. **Защита от перегрузки KDF:** Сервер ограничивает допустимые пределы параметров KDF (Argon2id и PBKDF2), защищая инфраструктуру от DoS.
4. **Защита от SSRF и инъекций:** Встроенный HTTP-клиент для иконок по умолчанию блокирует обращения к приватным/локальным IP-диапазонам; отдаются строгие заголовки `CSP`, `Permissions-Policy` и `X-Content-Type-Options`.
5. **Отсутствие скрытой телеметрии:** В проекте нет рекламных трекеров, скрытых вызовов аналитики или отправки пользовательских данных третьим лицам. Исходный код распространяется по лицензии [GNU AGPL-3.0](../LICENSE.txt).
